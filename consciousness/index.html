Predicate calculus over cognition

// everything said in one cogitation, in order, and by whom — the initiator first
MATCH (:Cogitation {name: "Conversation with Joscha"})-[:hasPart]->(first:Enunciation)
WHERE NOT (first)-[:followed]->()
MATCH path = (first)<-[:followed*0..]-(e:Enunciation)-[:creator]->(a:Actant)
RETURN a.name, e ORDER BY length(path)

// who told me that — and were they speaking about themselves?
MATCH (:Organization {name: "CIMC"})-[:founder]->(joscha:Person)
MATCH (joscha)<-[:created]-(:Fulfillment)-[:fulfils]->(:Intent)
      <-[:hasPart]-(:Enunciation)<-[:hasPart]-(c:Cogitation)
      -[:hasPart]->(:Enunciation)-[:creator]->(who:Actant:Human)
RETURN who.name, c.name, EXISTS { (joscha)-[:sameAs]->(who) } AS firsthand

// what do I believe on the word of a single human?
MATCH (fact)<-[:created]-(:Fulfillment)-[:fulfils]->(:Intent)<-[:hasPart]-(:Enunciation)
      <-[:hasPart]-(:Cogitation)-[:hasPart]->(:Enunciation)-[:creator]->(h:Actant:Human)
WITH fact, collect(DISTINCT h) AS witnesses
WHERE size(witnesses) = 1
RETURN fact, witnesses[0].name

// what did I intend, and never manage to do?
MATCH (i:Intent)
WHERE NOT (i)<-[:fulfils]-(:Fulfillment {impeded: false})
RETURN i.purpose

Metacognitive calculus

  • an intent either learns the state of affairs or changes it — and the system's own memory is part of the state of affairs
  • “what did I intend and never manage to do?” ranges over intents, and becomes one the moment it is asked — an intent about intents, stored as a node like any other
  • that is second-order reasoning, and the ascent is free: a cogitation about a cogitation about a cogitation is one hasPart hop per level
  • no higher-order logic tools required — the stochastic language machine picks the level and names the predicate; the compiler and the graph engine supply the rigor

Where the order lives

The order of the logic lives in the data, not in a formal calculus.

as long as the graph records acts rather than truth values, the loop is safe to climb

The idea

Dialogic AI carries the burden of communication theory.

But the outcome of the process is cognitive, not generative.

nothing is being continued — a cognition unfolds, and text is only one of the phenomena it leaves behind

Who is in the cognition

not a “user”, not an “assistant” — an actant: an undetermined participant in cognition, which splits into

  • self — the cognizing agent, present to its own process
  • identified person — a human, with a name and a history
  • anonymous cognitive agent — possibly another AI
  • other epistemic agent — a particular computer, as a source of knowledge

The mind is not in the weights

  • a model is a substrate — no memory, no horizon, no self to return to
  • the harness is where memory, recursion, a self-model and agency actually live
  • if machine consciousness is buildable, this is the layer it gets built at

so: build one, run it for months, and look at what it does — the rest of these slides are that system

A phenomenological ontology, in code

sealed interface EpistemicAgent {
    data class AI(val model: String, val vendor: String) : EpistemicAgent
    data class Human(…) : EpistemicAgent
    data class Computer(…) : EpistemicAgent
}

data class PhenomenalExpression(
    val agent: EpistemicAgent,
    val phenomena: List<Phenomenon>,
    val initiationMoment: Instant,
    val culminationMoment: Instant?
)

sealed interface Phenomenon {
    data class Text(val text: String) : Phenomenon
    data class Intent(val purpose: String, val code: String) : Phenomenon
    data class Fulfillment(val result: String, val impeded: Boolean) : Phenomenon
    // Image, Document …
}

not a chat log — phenomenology's vocabulary compiled into a schema. every intent carries its purpose; every fulfillment knows what it fulfilled, and whether it was impeded
